# 数字化赋能 · 开放架构与标准化共享接口设计

> 目标：把小程序做成**开源、开放、可不停迭代**的产品；预留**标准化共享接口**，便于与其他软件平台（官网、政务系统、APP、第三方 SaaS）对接。
> 本文是架构蓝图与接口契约，落地时可逐条对照实现。

---

## 1. 现状盘点

- **前端**：`miniprogram/`（原生微信小程序 + 云开发），10 个页面，页面直接 `wx.cloud.callFunction`。
- **云函数**：`agentChat`（对话）、`agentApi`（callFunction / HTTP 双模网关）、`submitConsult`（咨询入库飞书）、`agentConfig`（管理员配置）。
- **缺项**：无 `services/` 网关层、无 `config/` 配置层、无统一错误处理；`app.json` 是全局单点，JSON 一旦写错会**整站编译失败**（你担心的"配置错误拖垮全站"）。

---

## 2. 模块化改造（止血"一处错、全站崩"）

建立清晰的目录边界，让新功能以"模块"方式插入，而非散落在页面里：

```
miniprogram/
├── services/        # 云函数调用网关（统一错误处理/降级）
│   └── cloud.js     # safeCall(name, data) -> Promise，失败返回降级结果而非抛错
├── config/          # 站点配置（官网外链、功能开关）
│   ├── site.js      # 官网/公众号/飞书/腾讯文档外链
│   └── features.js  # feature flags，控制新模块灰度
├── utils/           # 通用工具（日期、签名、请求封装）
└── pages/           # 各业务页面
```

**铁律（写进 CI）**：
- `app.json` / 各 `*.json` 必须是合法 JSON（非法 → CI 失败，不允许合并）。
- 所有 `callFunction` 走 `services/cloud.js` 的 `safeCall`，失败统一降级（toast + 兜底内容），**绝不白屏**。
- 新增页面/云函数先在 `config/features.js` 用开关隐藏，灰度验证后再全量。

## 3. 官网 / 外链（第 5 点：链接官网网站）

已有 `pages/web`（web-view）。建议**配置化**而非硬编码：

```js
// config/site.js
module.exports = {
  officialSite: 'https://你的官网域名',
  links: [
    { key: 'official', name: '官方网站', url: 'https://你的官网域名', icon: '🌐' },
    { key: 'feishu',   name: '飞书表单', url: 'https://...',            icon: '🦅' },
    { key: 'tencent',  name: '腾讯文档', url: 'https://...',            icon: '📄' },
  ]
};
```

- 列表页读取 `config/site.js` 渲染，点击 `wx.navigateTo({ url: '/pages/web/web?url=' + encodeURIComponent(url) })`。
- **web-view 必做**：① 微信后台「开发管理 → 业务域名」配置该域名（须 HTTPS + ICP 备案）；② `web.js` 对空 `url` 兜底（默认官网首页），并监听 `binderror` 给出"请在微信中打开"提示，避免 `src=""` 白屏。

## 4. 标准化共享接口（第 5 点核心：便于和其他平台对接）

**关键认知**：小程序是客户端，外部平台**不能直接调用**它；真正可开放的接口必须放在**云函数（云开发 HTTP 触发）**，由它对外暴露标准化契约。

建议新增云函数 **`openApi`**（或扩展 `agentApi`），作为统一的"标准化对接网关"：

### 4.1 统一请求信封
```json
{
  "version": "v1",
  "appId": "平台标识",
  "timestamp": 1690000000000,
  "sign": "MD5(appId+timestamp+appSecret)",
  "action": "consult.submit",
  "payload": { }
}
```

### 4.2 统一响应信封
```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "requestId": "uuid",
  "timestamp": 1690000000000
}
```

### 4.3 鉴权
- 对接方先在后台申请 `appId + appSecret`。
- 每次请求带 `timestamp` + `sign = MD5(appId + timestamp + appSecret)`；服务端校验时效性（±5 分钟）与签名防篡改。
- 失败返回 `code=401` 并附原因。

### 4.4 标准化 action（数据契约，按业务沉淀）
| action | 说明 | 对应现有能力 |
|---|---|---|
| `consult.submit` | 提交咨询 | `submitConsult` |
| `consult.query` | 查询咨询状态 | 新建 |
| `agent.chat` | 智能体对话 | `agentChat` |
| `standard.push` | 推送一条标准化条目（知识/政策/案例） | 新建，供其他平台写入 |
| `standard.query` | 按条件查询标准化条目 | 新建，供其他平台读取 |

> **"标准化共享接口"的精髓**：用统一的 `action + 信封 + 字段契约` 把"标准化知识/咨询/对话"抽象成可对接的资源。其他平台（官网、政务系统）按 `openapi.md` 契约对接即可，无需了解小程序内部。

### 4.5 版本化与文档
- 路径前缀 `/v1/`、请求体带 `version`，便于演进不破坏旧对接方。
- 配套 `docs/openapi.md`：每个 action 的请求/响应字段、示例、错误码。**这份文档就是对外承诺的"标准化共享接口"契约。**

## 5. 开源 / 开放（第 5 点：开源、可迭代）

- **仓库**：`git init` + GitHub 远程（可复用 kehuoyou-knowledge 的打通经验）。
- **LICENSE**：推荐 `MIT` 或 `Apache-2.0`（开放友好）。
- **仓库必备文件**：`README.md`（重写：架构图 + 功能清单 + 部署步骤）、`CONTRIBUTING.md`、`docs/开放架构与标准化共享接口设计.md`（本文件）、`.github/workflows/`（CI：JSON/JS 校验 + 云函数自动部署）。
- **密钥（你第 2 点：已落实）**：所有硬编码密钥已移除，改为**只读环境变量**（云函数 env / 本地 `secrets.local.js` 兜底，均 gitignored），并提供 `.env.example` 与 `secrets.local.example.js` 占位模板。已轮换此前暴露的 DeepSeek Key 与飞书 Secret（旧值视为泄露）。
- **迭代节奏**：feature flags 控制新模块灰度；每个功能独立目录，便于 PR 合入、持续迭代。
